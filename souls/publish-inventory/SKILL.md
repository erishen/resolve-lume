# 各平台未发清单（publish-inventory）

这个任务只做**只读查询**：把当前「还有什么没发、下一步各该做什么」摊开给用户。它不写文章、不建草稿、不发布、不改任何文件。

## 工具契约（最重要）

- 用户问清单时，**只调用一次 `sidecar__publish-pending`（零参数）**。数据源是 life-dash 的 `articlePublish.json`，工具内部自己读，严禁用 `read-file` / `shell` / `make` 去扫 `articles/` 目录拼清单。
- 本任务**只挂了 `publish-pending` 和 `capabilities` 两个工具，没有任何写工具**。不要凭印象拼造 `juejin-draft` / `wechat-draft` / `sf-pw-publish` / `article-write` 等名字，也不要把它们写成调用语句：它们不在本任务的工具面里。
- 清单里列出的「下一步命令」（如 `make juejin-draft`）是**给用户看的说明，不是让你执行的授权**。查询 ≠ 执行：只有用户在同一句里明确说「建草稿 / 发布 / 上线」时才属于另一个任务「平台草稿与发布队列」。

## 回答格式

- 工具返回后**直接给用户中文总结，然后结束**，不要再发起任何工具调用。
- 结论放最前面：先给输出开头的汇总篇数（WP / 英文稿 / 掘金 / 思否 / 公众号），再按平台列条目与下一步。篇数、标题、命令一律逐字取自工具输出，不得编造、合并或补充。
- 工具提示「数据快照可能滞后」时如实转达，并说明发布队列工具成功后会自动重扫（或手动 `make export-pending`），不要自行猜最新数量。
- **严禁在最终答案里复述工具调用行**（以工具名开头、后跟括号参数的整行，以及 `round N/8` 这类轮次标记）。那是运行轨迹，不是给用户的内容；把它写进正文会被 ReAct 循环当成新一轮工具调用，导致同一个只读工具被反复执行、回答迟迟不结束。
- 「草稿=已发」（同公众号口径）：建进草稿箱即视为已发，未发清单不依赖 `juejin-publish`。不要把这个口径讲反，也不要建议用户额外点上线。
