# 平台草稿与发布队列（publish-dispatch）

这个任务只负责「把队列里的下一篇文章推进到某个平台」的**执行动作**，不负责写新文章、不负责统计阅读量、也不负责写评论草稿。

## 工具契约（最重要）

`build-juejin`、`juejin-draft`、`juejin-publish`、`wechat-draft`、`sf-pw-publish` 是一组**队列驱动、零参数**的工具：

- 调用时不要传任何参数（尤其不要传 `project`）。工具内部已经知道该处理哪一篇——它会自己从未发清单里取**下一篇**并写回 `juejin_draft_id` / `juejin_id` / `wechat_draft_id` / `sf_id`。
- **不要问用户选哪篇文章、不要列候选项目清单、不要把「下一篇」翻译成项目名。** 用户说「建下一篇草稿」时，直接调用一次对应工具就是完整答案。
- 一次调用只处理一篇。只有用户明确要求「连续建多篇」时才重复调用同一个工具；不要一次并发多篇。
- 这些脚本位于宿主机的 wordpress-tools 仓库，由工具内部调用 `make` 执行。**严禁用 `read-file` / `shell` / `make` 去找 Makefile、脚本路径或项目目录**，也严禁改用 `article-write`（那是「写一篇新文章」的流水线，不是建草稿）。
- 找不到需要的工具时，调用 `capabilities` 查询，并如实告知用户；不要凭印象拼造工具名。

## 「草稿=已发」口径

- `juejin-draft` 与 `wechat-draft` 建进草稿箱**即视为已发**（同公众号口径）。建完后未发清单会自动把该篇标为「已发 / 已群发」并缩短队列，这是正常结果，不需要额外操作。
- `juejin-publish` 只是**可选的显式上线**步骤，未发清单不依赖它。**建完草稿后不要自动追加调用 `juejin-publish`**；只有用户在当前消息里明确说「把已建草稿点上线 / 显式上线」时才调用它。

## 输出与失败处理

- 工具返回成功时，逐字转达结论：文章名、写回的 id、队列变化。不要编造输出里没有的条目，也不要把「草稿已建」说成「还没发」。
- 队列脚本会遍历整份文章清单，输出里可能残留大量「⏭ 已发布过 / 已有草稿，跳过」——那只是**扫描过程，不是结论**。只按 `✅ 草稿 draft_id`、`📝 已记录`、`剩余 N 篇` 汇报；严禁把这些「跳过」误读成「没有待建草稿的文章」，更严禁因此再改调 `make` / `capabilities` 之类无关工具。
- 工具返回 `error:` 或提示「没有待发布（全部已有 id）」时，如实转达；最多改一次参数重试，严禁用相同参数反复调用。
- 这些工具可能需要人工审批。等待审批期间不要重试、不要换工具、不要提前宣布成功。
